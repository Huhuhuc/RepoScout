# 证据缺口驱动补查

用户已批准按路线推进：识别需求证据缺口 → 定向补查 → 更新比较矩阵。实现沿用单 Agent 架构，不增加模型服务依赖或付费调用。

## 规则

1. review_evidence 接收完整草稿，运行已有引用校验，保存矩阵快照；识别缺失证据、未知、冲突和只有社区反馈的条目，优先必须条件。
2. investigate_gaps 只接受最近检查中的缺口，最多两轮、每轮三个目标；每轮后必须重新检查矩阵。相同目标/关键词/路径重复请求被拒绝。
3. 指定 document_path 时读取固定 commit 文档，否则查询仓库 Issues；同时在已采集资料中按关键词寻找候选片段。候选片段不是证据，不自动形成结论。
4. 模型保存准确摘录并更新完整矩阵；最终报告必须与最近检查一致。若缺口仍存在且预算足够，至少执行一轮补查后才能提交。
5. Issue 不能单独支撑支持/不支持判断；没有搜索结果不能证明不支持。语义支持关系仍需人工或后续评测复核。
6. 子工具也计入工具预算；失败记录保留，预算耗尽保留最近通过结构校验的矩阵。

## 界面与导出

比较报告显示待核实需求、缺口原因、补查轮数、目标和结果，以及从初步矩阵到最终矩阵的状态/证据变化。Markdown/JSON 均包含这些记录。旧历史报告兼容显示。

## 验证与边界

离线测试覆盖 unknown 到 supported、社区反馈拒绝确定判断、空结果、重复查询、跨候选目标、补查轮数、预算与失败处理。模拟 DeepSeek 五次响应测试覆盖检查 → 补查 → 保存证据 → 复查 → 提交，未发送任何真实模型请求。

GitHub 无密钥模式显示缺口，仍不自动进行语义判断。真实 DeepSeek 的工具选择、关键词质量和引用语义正确性尚未验证。未增加外部网页采集或向量检索。两个补查轮次是上限，最多六个目标；无法保证覆盖所有需求。
