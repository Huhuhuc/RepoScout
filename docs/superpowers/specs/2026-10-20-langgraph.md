# RepoScout LangGraph 执行器第一阶段

用户已选择先升级原项目，沿用此前提出的 LangGraph、持久化、评测顺序。

## 本轮范围

保留 legacy 执行器作为默认基线，增加可从工作台选择的 langgraph 执行器。
复用模型服务、资料工具、快速核查、报告校验与同模型复核。
图拆为 prepare、decide、tools、review、finish；条件边负责继续调用或停止。
状态保存已执行工具反馈、未执行调用、无进展次数、预算、资料和报告。
SQLite checkpointer 保存节点边界；通过原任务 ID 恢复服务重启后的任务。

保持两种语义独立：原“继续调查”创建新任务并给新预算；“恢复图执行”沿用同一任务、累计预算。
不将数据缓存声称为跨任务长期记忆，也不声称本轮实现多 Agent 或新规划模型。

## 故障约束

模型或资料请求发出后、检查点落盘前崩溃，不能确认远端请求是否执行或计费。
每个图节点执行前写入持久 in-flight 标记，节点检查点写完后清除。
重启发现未确认节点时拒绝自动重放，提示创建关联新调查；不承诺 exactly-once。
取消检查仍由原任务状态控制。恢复仅允许 interrupted 且 engine=langgraph。
保留累积活动执行时间；服务停机时间不计入五分钟执行预算。
检查点不包含 API 密钥、GitHub token 或 provider 配置。

## 验收与计划

1. 实现 graph state、条件路由、SQLite checkpoint、未确认执行保护。
2. 接入请求参数、页面执行器选项、节点轨迹和恢复入口。
3. 脚本服务验证错误工具反馈、最终提交、预算停止；重建 runtime/服务验证恢复。
4. 对照旧执行器报告；完整旧测试回归；输出离线演示记录。
5. 不自动发起付费评测、不发布远端。真实模型效果仍以既有记录为准。

## 后续阶段

结构化计划编辑、跨任务偏好记忆、复核失败后自动补查、多 Agent 和真实重复评测另行实现。
