# RepoScout 第一版设计

状态：方向已获用户认可；本文件为实现前的具体范围。

## 目标和边界

构建独立的开源项目技术选型 Agent，未来使用独立目录 RepoScout 和独立 Git 仓库。目标用户是需要比较开源方案的开发者。第一版输入中文需求，调查最多三个候选仓库，输出带证据的比较报告和完整执行记录。默认预算为 20 次工具调用、最多 2 轮补充调查、单任务 5 分钟；超限后输出部分报告并列明未解决问题。

## 方案选择

选择独立实现轻量单 Agent 循环，参考 GPT Researcher 的规划、来源追踪与报告组织方法。相比直接二次开发完整 GPT Researcher，可清楚展示个人实现并控制范围，但需要自行实现状态管理和评测。相比一开始采用多 Agent，单 Agent 更容易调试和建立对照基线，之后有证据证明需要并行时再扩展。

## 用户流程

用户填写需求、必须条件和可选候选仓库。需求不足时返回澄清问题；未回答前不开始调查。启动后展示计划、工具动作、证据和剩余预算。完成后展示候选比较、满足或不满足或未知的约束判定、引用、推荐理由和未解决问题。支持查看历史任务、取消运行、导出 Markdown 和 JSON。

## 技术架构

后端 Python、FastAPI、SQLite；前端 React、TypeScript。调研核心不依赖 Web 框架，通过模型适配器和工具接口独立运行。后台工作线程承担第一版本地任务；任务重启后标记 interrupted，保留证据，用户明确重跑才创建新任务，不自动产生付费调用。

模型适配器支持 Mock 和 DeepSeek 的兼容接口。默认 Mock，不复制任何既有项目的密钥，也不自动调用付费模型。Mock 仅用于验证流程，界面和报告明确标注，不能被计入真实模型质量指标。

## 四类工具

1. search_repositories：通过 GitHub API 搜索仓库；记录查询、排序条件和抓取时间；无令牌也可运行，限流时报告剩余额度或恢复时间。
2. read_repository：读取仓库元数据、README、许可证信息、最新发布及有限数量的相关 Issue。保存仓库默认分支或发布版本信息；Issue 内容仅作为有时间范围的讨论证据。
3. read_webpage：获取公开官方文档，保留来源和正文段落。第一版只支持静态 HTML 和 Markdown；不声称支持需要登录或 JavaScript 执行的网站。校验 URL、DNS 和重定向目标，禁止内网地址；限制响应大小、超时和重定向次数。
4. save_evidence：保存证据卡片，包含 URL、标题、原文、内容哈希、抓取时间、适用版本、相关调查维度。摘录必须是工具已读取内容的子串；证据 ID 由系统产生。

工具输入由结构化模型校验。网络错误有限重试，限流保留明确错误，不伪造资料。外部网页和 Issue 作为待分析数据，不能覆盖系统指令或触发任意命令。

## Agent 循环和报告

模型先生成调查计划，再根据当前证据选择工具。每轮检查预算、取消标志和证据缺口；需要补查时允许最多两轮。报告采用结构化结果，事实条目必须附有效证据 ID；推断和建议单独标注。后处理只能校验证据存在、摘录来源和链接关系，不能宣称自动证明所有引用语义正确。缺少证据的能力标记 unknown，而非推断为支持或不支持。

## 数据和接口

实体为 Task、Step、Evidence、Report，各记录 task_id。Task 保存需求、模式、模型、配置快照、预算、状态和错误。Step 保存动作、参数摘要、耗时和结果；不保存密钥。Report 保存比较表、事实依据、推荐及未解决问题。

接口覆盖创建任务、读取任务、读取执行事件、取消任务、查询历史和导出。前端通过 SSE 接收持久化事件，断线后以事件序号补读。取消采用协作式停止，正在进行的网络调用受超时限制；取消后禁止继续提交报告。

## 页面

中文工作台：需求输入区、任务进度区、证据列表和比较报告。黑灰底色，少量暖橙强调色。证据可点击查看摘录和来源。执行模式和资料时间可见。

## 验收和评测

功能验收覆盖一个需求调查最多三个仓库、预算到达、网络失败、限流、取消、重启中断、证据导出和 SSE 断线补读。

固定离线资料集至少包含 12 个任务，覆盖条件不满足、资料缺失、资料冲突和过期资料。固定快照用于可复现评测，实时网络调查另外记录抓取时间，不混合比较。对照基线为一次检索直接回答，实验组为计划、工具调查和缺口补查。指标为约束判断正确率、人工标注的引用支持率、未知项处理、工具调用数、耗时和实际模型返回的用量；无用量信息时标记 unavailable。

自动测试验证 Agent 控制逻辑、工具校验、引用结构、取消和预算；真实模型报告由固定样本与人工复核评测。简历只记录已完成和实际测得的成果。

## 实施顺序

依次完成核心循环和离线资料工具、GitHub/静态网页读取、任务持久化与 API、前端工作台、固定评测和项目说明。第一版完成后再考虑多 Agent、向量检索和浏览器自动化。
