# 冻结资料评测

这是一组 12 个手工编写的合成案例，仓库和资料是虚构的，不用于证明真实 GitHub 项目存在。真实仓库检查另见 `docs/github-live-verification.json`。

覆盖明确支持、文档补充、资料缺失、云端限制、社区传闻、资料冲突、版本变化、提示注入、免费版限制、中文资料、资料读取失败和明确不支持。预期标签及依据片段留在评分器，模型只看到任务及工具返回的资料。冻结运行器禁止外部资料 HTTP 请求，真实模型 API 仍需要联网并计费。

```powershell
# 只校验数据，不调用模型
.\.venv\Scripts\python.exe -m evals.run
# 明确启用真实模型，会产生费用
.\.venv\Scripts\python.exe -m evals.run --live --max-cases 12 --output evals/results/new-run.json
```

2026-10-14，deepseek-flash，每个案例每种策略各运行一次。原始输出：[2026-10-14.json](results/2026-10-14.json)。

| 总耗时（秒） | 38.34 | 271.25 |

调查模式在 pdf-doc、conflict、version、restriction、chinese 五项取得额外正确判断；issue-only 和 conflict 实际执行了缺口补查。其他案例可能直接读文档或保留未知，并非每个案例都执行补查工具。

评分规则：状态必须与人工标签一致；确定性判断必须命中人工标注的原文依据；冲突必须覆盖两方依据；所有引用须出现在实际读取的资料中。结果文件的 citation_support 是固定依据片段命中率，不能视为通用语义判断指标。

限制：基线只能看 README，而调查模式可取得额外文档，因此比较的是“采集＋调查”整体收益，不是同资料条件下的纯推理提升。样本少、资料为合成、每项只跑一次，不能宣称真实任务准确率 100%。调查模式花费约 29 倍 Token、7 倍时间；当前尚未完成同资料消融、多次重复和更广泛真实仓库评测。Token 不等于账单金额，未估算账户实际收费。
